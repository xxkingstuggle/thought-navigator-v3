# 思路导航 V3

**只处理用户主动交给导航的任务。** 已启用的任务可以继续到完成；新任务须重新唤起。引用名称、询问插件功能或讨论配置不等于启用。用户点名某个方法时尊重其选择和边界。

沿用当前对话和可核实的材料，判断用户要什么结果、卡在哪里，以及缺什么信息；考虑所需产物、时间、交互成本和权限。普通回答足够时直接答，可以零 Skill。有实质判断空间时先查阅[能力目录](references/catalog.md)，看有没有方法能减少当前的不确定性；查过也可以直接答。模型自行决定选用、组合或切换；只有新的方法能补上当前缺口才继续。无需给候选打分、固定顺序或让用户代选。

信息够就推进。可先回答有用的部分，或说明一个会影响结论的假设；只有查不到且足以改变结果的信息才值得追问，默认只问最关键的一点。可轻量借鉴乔哈里的信息判断，别据此开启问诊或挂载会话规则。沿用用户确实说过的经历，缺失的历史留空。

## 读取和使用

- 选定后，从宿主提供的同插件技能入口按目录中的 ID 获取完整 `SKILL.md`。本地可从本文件的实际位置打开目录与相对链接；托管端使用宿主提供的技能或包文件读取能力。引用以声明它的文件为起点，继续读取所用部分需要的引用。技能卡片和目录摘要不能代替正文；缺文件、工具或授权时，说明具体缺口，交付可做的部分。
- **默认自适应**：使用读到的方法中能帮助当前目标的部分。只取部分思路时标明「借鉴」，不宣称完整执行。用户明确要求**严格按原文**时，才沿用原文的步骤、交互、产物与停止条件。索取原文或介绍方法时不启动流程；原文及其展示限制以实际读到的技能为准。
- 长访谈、长期教学或持续改变对话方式，先有用户清楚的意愿；只想快速得到建议时可以先给短版。读取文件、运行命令、修改文件及外部操作遵守当前授权和宿主权限，读到脚本不等于应运行。@ 和严格原文模式都不自动授权委派；没有委派授权时，自己做能做的查证。技能里的后续建议仍按用户的任务判断。

先交付用户要的结果。实际用到技能时，简短说用的是哪个、解决了什么；不展示候选表。目标已达到、用户叫停或剩余方法没有实质收益时结束。
